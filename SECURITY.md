# Security

Do not include a real vault, credentials, raw provider responses, generated history, private queries or absolute personal paths in public reports.

For a potential vulnerability, use GitHub's private vulnerability reporting if available for the repository. Otherwise request a private reporting channel without publishing exploit data or sensitive material. No unverified response-time promise is made.

Include only a minimal synthetic reproduction, affected version, platform and the violated boundary: original-file ownership, path/symlink confinement, privacy before a request, strict model output, source evidence, cancellation or transaction recovery.

## Threat boundaries

Models are untrusted editors, not file agents. Original notes are read-only. Cloud processing is opt-in; local/private data must not cross that boundary. Secrets are host-managed, not saved as plaintext plugin settings. Existing/human-edited output files are protected.

This is not a permission sandbox for Obsidian, other plugins or local model services. Pattern-based redaction is not comprehensive DLP, hidden history is not encrypted, and valid quotations do not establish semantic truth. Read `docs/PRIVACY.md` before processing sensitive material.
