# Implementation brief — Third Brain

Read PRODUCT-SPINE.md and AGENTS.md first. Build a complete installable initial release, not a description or stub. Scope: a desktop Obsidian plugin in TypeScript; independent MIT implementation. Use host SDK 1.13.1, minAppVersion 1.11.5, plugin id third-brain, name Third Brain. Do not copy competitor or private code. Do not access files outside this repository; all demo/test data must be authored synthetic.

## Architecture

A browser-compatible pure TypeScript core (sources, privacy, fragments, strict model schema, facets, candidate ranking, transaction planning) and an Obsidian adapter. A desktop native HTTPS/local HTTP transport can use Node modules to enforce AbortSignal, timeout, no redirects and request-size/response-size limits; mark desktop-only. No server/companion requirement. Vault operations use host APIs. Store the owned derived index and validated journal under the configured generated folder's reserved .third-brain subdirectory; plugin settings live in the plugin directory and contain the secret ID only, with the API key obtained from app.secretStorage. No plaintext-key fallback.

Default mode: local lexical/extractive baseline with zero model requests; honest labels 'Local excerpt'/'本地摘录', not fake AI. Optional local OpenAI-compatible loopback model. Optional cloud OpenAI-compatible model requires explicit consent and HTTPS, no nonloopback HTTP, no URL credentials/query/hash, no redirect following, secret mandatory. local/private metadata must be inspected before any text transformation and excluded from cloud indexing, vocab or queries. No prompt/filename/path leakage: prompts use opaque IDs, bounded redacted text and only public/nonprivate vocab. Credentials in content block model calls; common PII redacted. Disclose that regex DLP cannot guarantee comprehensive privacy.

Core fragment shape: stable id, source evidence [{sourceId, relativePath, sourceHash, quote, start,end}], title, summary, kind, facets {topics,concepts,mechanisms,atmosphere}, optional mechanism conditions/caveats, extraction mode, updated time. Program controls IDs and paths, never model. Strict JSON fully consumed, versioned schema, unknown keys rejected, all evidence quotes must be present in the sanitized input; recover original offsets only when exact mapping exists. Sparse material may return insufficient-context or zero facets. No default arbitrary domain tag.

Local mode should split readable Markdown by headings/paragraphs and retain meaningful sentences without making up summaries. Support Markdown and Canvas text nodes; Excalidraw encoded drawing data excluded; Kanban frontmatter preserved for privacy then strip for extraction. Meaningful one-line notes kept without forced facets. Use immutable one-read snapshots and hashes; no source writes ever. Generated AI directory default 'Third Brain' excludes existing owned output only, not all user notes there: user-authored originals anywhere stay read-only. Plugin directory ignored as source; generated files use safe stable-ID filenames and explicit ownership headers/content hashes. Prefer conservative protected conflicts over overwrite.

Index/maintenance: manual default, daily/weekly optional; checks while app open, overdue once; no per-keystroke model calls or click learning. Source-hash diff and generation config signature; unchanged no model call/no output rewrite. Source deletion/rename observed, candidates only from currently available source evidence; ambiguous content-hash moves not inferred. Build all valid new fragments and relations before commit; preserve previous complete revision if schema/network/source CAS fails. Staged durable journal for owned writes, state and rendered fragments; validate relative targets and backup hashes on recovery; fail closed on corrupt manifest/unknown schema; never overwrite unowned or human-edited files. Cancellation stops requests and drops late results. Global single-flight prevents overlap.

Dedup: exact canonical semantic body within source can merge quote evidence; cross-source exact excerpts share one fragment with multiple provenance, distinct ideas never collapse just because titles match. Similar but nonidentical entries can be grouped without inventing semantic equivalence. No duplicate files on rerun.

Retrieval: Chinese char bigram+Latin tokens, TF-IDF sparse candidates; topics, concepts, mechanisms and atmosphere separate explanatory channels. Explicit user tags/links may aid retrieval without telemetry. Low direct same-topic; medium adds shared mechanisms; high permits cross-domain mechanism analogies with source evidence and caveat. Never return zero-score junk just to fill top-K. Natural idea query can optionally be interpreted by authorised AI into bounded facets; must not require the user to know tags. Current-note activation is explicit button and snapshots editor once. A blank/uninformative note displays an honest request for a topic. No insertion in source notes.

## User experience

One native sidebar view: natural-language idea input; low/medium/high association select; 'Find connections' primary; current-note context affordance; clickable facets; each result: fragment/excerpt, reason type and plain-language explanation, provenance quote and source open button, generation/date/stale status, caveat for mechanism/analogy. No giant dashboard card wall, no auto popup while typing. Clear empty/first-use/working/cancel/error/offline/conflict states. Initial empty view offers Index notes and explicitly synthetic demo instructions, not hidden fake results. Settings separate: processing mode, schedule, source excludes/limits, generated folder, endpoint/model, SecretComponent, cloud consent. Chinese/English locale dictionary with automatic language fallback and explicit override. Host CSS variables and scoped flat styles; keyboard labels, focus, narrow view and reduced motion.

A faithful browser test harness reuses the real view renderer with an in-memory adapter and synthetic fixture data. Label harness as such; this helps Playwright verify full UI. Production adapter/real Obsidian test remains separate evidence.
