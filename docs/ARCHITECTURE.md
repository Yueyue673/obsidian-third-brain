# Architecture

One desktop Obsidian plugin, one activation surface, no companion service.

## Boundaries

- `src/core/`: host-independent source preparation, privacy policy, strict model-response schema, fragment extraction/reconciliation and local retrieval. Model output is data, never an instruction to operate files.
- `src/sources.ts`: byte-level source snapshots and SHA-256 revisions; canonical vault-relative paths; symlink rejection; source-set compare-and-swap. Originals are read-only.
- `src/runtime/store.ts`: ownership-protected derived Markdown, strict persisted state, staged writes, a validated recovery journal and generated-history handling. A folder name cannot establish ownership.
- `src/runtime/transport.ts`: bounded native HTTP(S), explicit model/endpoint selection, loopback/cloud policy, no redirects, cancellation and timeout. No implicit service or model starts.
- `src/controller.ts`: single-flight refresh/search, snapshot/config coordination, live-evidence checks and visible safe status. No model reranking of private fragments. Before a model request may carry note text, each pending source is re-read at that request boundary; cloud vocabulary is collected, re-verified and re-checked against current exclusions/donor revisions immediately before it is sent.
- `src/main.ts`: Obsidian view, settings, secret selector, source opening and app-open-only schedule.
- `src/ui.ts`: text-only DOM rendering shared by the host and a labelled synthetic browser harness. Source/model strings are not interpreted as HTML.

## Refresh

Read each original once into an immutable snapshot. Classify local/private and sensitive input before conversion or model calls. Use unchanged source hashes and a generation signature to avoid repeated model work. Build and validate the complete next revision before source recheck and owned commit. A failed analysis never returns a partial next revision. Optional source read/list/verify signals and per-source progress preserve zero-argument adapter compatibility; cancellable waits reject late results, and the production reader checks between sources/async steps. Core processing completion is not host commit completion. Trusted relative-path/stage/reason diagnostics are attached to actual source failures with a private WeakMap; external similarly named properties are ignored and original exception identity/categories are retained. Request-boundary privacy/identity/dictionary proof failures stay global, with existing bound donor I/O locations preserved. Status retains last progress and distinguishes no prior complete index, pre-commit failure and unknown commit outcome; the bilingual panel renders only controlled fields, not arbitrary exception text or model output. These diagnostics are transient: v1 state, generated Markdown, generation signature and model wire remain unchanged. During filesystem commit, only the index state swap is atomic; see the journal/recovery limits below.

An in-memory recovery flag records any refresh failure/cancellation after commit starts. Before the next incremental refresh, the Controller awaits `StorePort.recover()` and a strict `load()`, checks cancellation after each await, and adopts only the validated saved revision. A durably saved revision with interrupted finalization is therefore reused rather than regenerated from an older in-memory index. A recovery refusal keeps the flag and unknown-outcome warning; it cannot start source analysis or a new commit. Recovery has no abortable host-I/O contract, so cancellation retains single-flight until the awaited operation settles. Explicit successful initialization consumes the flag; ordinary refreshes and pre-commit failures introduce no extra reload. The flag is transient, not a storage-schema, generation-policy or model-wire change.

## Activation

### Local primary and same-list context (unreleased)

Headings indented into an active local list item's content stay in that bounded authored group, not in the note's global ancestor stack. A dedented block first closes the old list; it can then establish ordinary heading scope. A contiguous dash underline below eligible plain item text is retained rather than mistaken for a thematic break. When that first paragraph begins on the item marker's line, eligibility uses its content column rather than the marker's indentation; the underline must belong inside that content and must not follow a blank line. Quoted/HTML/list/code-like content is not promoted by this exception. Other rules and code/hidden boundaries remain barriers, and an indented heading cannot reopen a blocked parent. Decoded Canvas evidence includes complete visible heading lines without changing AI primary/background parsing. Exact evidence and existing whole-group limits include this text; local generation upgrades once while frozen stored bytes remain readable. This follows the container distinction in [CommonMark list items](https://spec.commonmark.org/0.31.2/#list-items), not a full Markdown interpreter or inferred dependency classifier.

A top-level Markdown pipe table retains an immediately preceding visible paragraph or quoted introduction ending in `:` or `：`, even across blank lines. Recognition requires a header and equal-width delimiter row with at least two hyphens per cell (optional outer pipes/alignment colons, escaped pipes as text), following [Obsidian's table syntax](https://help.obsidian.md/advanced-syntax#Tables). The whole bounded table paragraph stays together with its header/rows; this does not classify row independence or arbitrary prose applicability. The introduction is separate exact evidence, participates in identity and combined size/evidence bounds, and can carry existing named-footnote/reference dependencies. Hidden introductions fail closed. Intervening headings, rules, code, hidden blocks or Canvas nodes break adjacency; non-colon prose, invalid headers and quoted/nested tables are not promoted. AI parsing/cache, schema and historical no-context saved-file behavior are unchanged; an explicit local refresh upgrades once.

Reference-style links retain their authored top-level definition as literal source context, not as executable/navigation data. Full, collapsed, shortcut and reference-image uses match single-line unescaped labels with case/space folding within the same note or Canvas text node. A definition starts at a block boundary with up to three spaces; destinations and optional single/double/parenthesized titles may occupy successive lines, with nonblank multiline titles. Complete spans and ancestor headings receive exact evidence; headings' named-footnote dependencies are included, but brackets inside destinations/titles stay literal. Duplicate matching or recognised unsupported/hidden definitions refuse the update; unresolved labels remain literal Markdown, not invented dependencies. Quoted/nested definitions, multiline/escaped labels and arbitrary prose dependencies are outside this bounded reader. Inline/code/escaped/wiki syntax is not a reference request. No URL fetch, new link button, schema or AI-policy change is involved. The existing combined text/evidence bounds include definitions; local generation upgrades once while exact historical bytes remain readable.

Named footnotes are explicit authored dependencies: a local primary retains required top-level `[^label]:` definitions, their indented continuation paragraphs and ancestor headings as separately verified quotations in its summary. Resolution uses exact labels within one Markdown note or one Canvas text node, follows transitive references once and terminates cycles. Escapes and inline code are not requests; missing/empty/duplicate definitions, hidden content and fenced code refuse the run. Referenced definitions are not also emitted as orphan excerpts; unused definitions remain available. This is bounded structural retention, not general Markdown reference resolution. Primary, footnotes and omitted siblings share the same text/evidence bounds; local identity includes the retained definitions. Legacy output remains byte-readable, local generation upgrades once, and AI primary/background inputs, cache policy, schema and historical saved-file browsing policy are unchanged.

Ordinary paragraph text followed immediately by a valid setext underline (`=` for level 1, `-` for level 2) supplies the same local ancestor context as ATX headings. Full authored heading lines, including the underline, are separate exact quotation evidence; equal/higher headings replace their scope. Blank-separated thematic rules and list/quote/HTML/code-like paragraph prefixes are not promoted into global ancestors. This is bounded structural retention, not a complete Markdown interpreter or a semantic dependency classifier. Decoded Canvas readable-quote verification recognises the full heading. The existing complete-context/evidence limits include it; only local generation changes, not AI primary/background input or cache policy. Legacy generated bytes still load unchanged and are retired only by an explicit successful local refresh.

Same-level standard unordered task items (`[ ]`, `[x]`, `[X]`) with the same bullet marker remain one complete local excerpt. Checked status does not establish that a preparation is dispensable. Descendants and existing labelled following qualifiers stay with the group; ordinary bullets, custom states, changed bullet/list types and existing structural boundaries end it. This conservative rule may retain unrelated checklist observations together and does not infer dependency. Complete-group text/evidence bounds, current-source checks and historical saved-file policy are unchanged; only local generation is invalidated, not AI input or caching.

Same-level roots in a numbered list with the same delimiter (`.` or `)`) remain one complete local excerpt, including their descendants and existing labelled qualifiers. Repeated/nonconsecutive numbers and loose blank lines do not prove independent steps. A delimiter/list-type change or an existing prose/heading/code/hidden/node boundary ends the sequence. This is conservative original-context retention, not dependency detection; unrelated enumerated observations may remain together. Ordinary unordered roots and a single numbered root's focused unordered children retain their existing policies. The complete group remains inside the same text/evidence bounds; only the local generation signature changes. Saved no-context generated files retain their existing historical-browsing policy, while old-card original actions require the complete current source endpoint.

Qualified unordered branches retain a focused `summary` and a separate optional `localContext` string containing omitted sibling subtrees in authored order. Both the default panel and generated Markdown show this source text explicitly, not only inside collapsed evidence. It is conservative context, not a classified dependency, editorial condition, facet or semantic connection. Only local `excerpt` fragments may carry the field; model output continues to reject it. Existing stored identities and generated bytes remain readable without reinterpretation. New local identity preserves line breaks and indentation in both primary and sibling text, normalizing only line-ending representation after outer trimming; it does not flatten authored structure or infer equivalent meaning. Complete structural copies may merge, with every donor retained and restrictive privacy preserved. The historical flattened digest remains a compatibility identity for the exact stored content, so old state can load and recover without rewriting its owned bytes; newly generated local fragments always use the structure-preserving identity. Explicit local refresh upgrades the local generation once. AI editorial identity and cache policy are unchanged. Conservatively distinct formatting may now yield separate local excerpts.

The complete original group is bounded before branch separation. Displayed primary length plus one joining newline plus context length must also fit the existing 16,384 UTF-16 code-unit bound: headings, introduction, parent and shared qualifiers occur in the primary once, not once per sibling. Context evidence counts in the same 256-entry limit, including cross-source merges. Core and store reject invalid shapes, missing per-donor quotation coverage and illegal AI use. Quotation coverage does not establish semantic dependence or equivalence. Only local generation is invalidated; AI input/background, wire schema and generation policy stay unchanged.

Every source action uses the complete endpoint, including sibling evidence. Main's controlled generated-file action additionally checks all current donors for these new contextual excerpts before opening saved text; legacy no-context derived-file behavior is unchanged. Context never enters lexical scoring or invents facets. Repeated source checks do not make file reads/opening atomic.

A natural-language idea is the primary input. Optional authorised model interpretation supplies bounded facets; local ranking uses content plus topics, concepts, mechanisms and atmosphere. Breadth changes eligible association channels, not privacy/evidence rules. A no-signal query produces no recommendations.

Long local `excerpt` primaries additionally use query-only overlapping 128-token passages at a 64-token step, including a full-sized final passage. Each passage uses the same full-document/facet corpus IDF; the greater of the whole-document cosine and best passage cosine supplies only the content score. This avoids diluting a late local match with all retained background without saving bare sentences or treating a window as independent evidence. Short primaries and AI fragments keep whole-document scoring. A winning passage has a bilingual lexical-hint explanation with complete original quotations and a reminder to read the full conditions/counterexamples; it does not classify opposing conditions or paraphrase equivalence. Sibling `localContext`, source filenames, persisted fragments/IDs, generation policies, facet boosts, breadth, network budgets and display limits are unchanged.

Before displaying or opening a quotation, check the current source revision, source identity and exact quotation span. Missing or changed evidence is not presented as an active reference. Multiple provenance is preserved when exact excerpts merge.

High breadth can reuse the existing render-v2 network calculation for a bounded, same-privacy one-hop suggestion from a direct mechanism/analogy seed: at most 3 seeds, 3 inspected neighbors each and 6 targets. Only shared mechanism edges qualify; neighbors cannot become seeds. Direct scores receive no bonus, and pure indirect scores stay below all direct matches. Both full endpoints carry source evidence, conditions and caveats and are rechecked for indexed membership, revision, identity, exact quotation, privacy and exclusions. The UI provides separate source buttons and preserves the existing controlled Open fragment action in both result sections. An opt-in query-only side channel retains at most six network-supported candidates before the ordinary ranking cutoff. The Controller preserves the current main seven, then checks up to two nonduplicate extra suggestions; low/medium and the default core result limit are unchanged. The summary names the extra count and the renderer separates the section explicitly. Exact rendered quotation objects are temporarily bound by WeakMap to complete one-hop proofs, so either original-source button rechecks both full endpoints and shared mechanisms, including old still-visible cards after a cancelled search. These are source-validation bindings, not click logs. Query-only metadata is not persisted; network/render bytes, schema and generation policies are unchanged. Repeated checks narrow but cannot eliminate check-to-use races because SourcePort does not offer atomic pair reads.

## Storage and sync

Derived Markdown is visible; reserved state and history are hidden. The validated **index state swap** is atomic; generated Markdown files are journaled and applied individually. A file browser or sync tool may therefore observe a mixture while commit/recovery is in progress. This is not an atomic swap of the entire folder. Recovery failure blocks the plugin rather than reporting success.

Portable Node file APIs do not provide compare-and-rename against every hostile filesystem race. Windows directory fsync is skipped; the journal/crash tests do not establish immunity to all power-loss or external-process interference. New stores bind an authenticated stage/backup inventory to the local marker, output folder and transaction; cleanup checks each file's expected hash. Unrecognised or edited artifacts and unverifiable legacy orphans are retained. Prospective work filenames are not cleanup ownership evidence. Unchanged authenticated staging can be pruned after finalization or on the next locked run; an unknown remnant preserves its directory. The marker is a local trust anchor, not protection against an actor able to rewrite all metadata. Retired fragment history is retained and not automatically compacted.

Secret values are held by Obsidian, with only their IDs in plugin settings. Hidden state is not encryption. Generated excerpts and history may contain note text, so users must review their sync/backup boundaries.

No telemetry, click history, dwell model, per-keystroke inference, mastery profile, remote index service or OS watcher is used.

## Runtime compatibility

The pure core can run in browsers, but production filesystem/network adapters require Node in desktop Obsidian. The manifest therefore declares `isDesktopOnly: true`; mobile support is not implied by a responsive sidebar or a browser test harness.

## Explicit facet activation

`FacetSelection` is a transient query-only channel/value, not a persisted state or model-wire field. Renderer, actual Main PanelPort and both demo boundaries forward it optionally; ordinary requests retain the previous three arguments. The controller rejects extra/inherited/accessor/symbol/unsafe fields, resolves the canonical safe label against a complete currently valid donor, skips model factory/interpretation and uses an empty lexical query plus that one facet channel. The explicit path does not enter natural-query interpretation; ranking/TF-IDF/network/display budgets are shared without changing their policies. Breadth limits still apply; high neighbors are suggestions, not strict equality.

Only this authenticated explicit four-facet path opts into `retainRankedContinuation`: a transient tail of the same once-scored, network-expanded and sorted corpus. Core callers retain their original requested/default limit; the Controller keeps its existing 30-candidate head; the Controller checks head then tail in the same score/ID order, skips known-invalid candidates and stops at main seven. It does not prefilter the scoring corpus, change IDF or rebuild the network. Unknown read/source-format/safety failures still abort the whole query rather than producing a partial result. The bounded extra-two channel and kind path are unchanged. Natural requests independently opt into `retainNaturalContinuation` only with non-empty text; the original explicit-facet empty-query guard remains intact. This is neither a new page nor complete pagination.

Selected results pass the existing full current-evidence/index-member/source-privacy/exclusion checks. Exact rendered evidence objects bind to a cloned endpoint through a short-lived WeakMap for original opening, including cancelled-search old cards; no click history/telemetry is stored. Editing/current-note activation clears the selection and invalidates pending renderer results; changing breadth keeps the choice and uses bilingual notices at inapplicable scope. These checks narrow existing check-to-open races, not make the SourcePort atomic.

## Stored-type activation

Transient `QuerySelection = FacetSelection | KindSelection` extends the same optional fourth PanelPort/Controller argument; actual Main already forwards it, and both demo endpoints retain it. Canonical types mirror the existing strict parser without changing model input/output, persisted Fragment/Facets/IndexState/relationships or generation signatures. A complete current donor is required before selecting `SearchOptions.kind`. The kind-only donor pass retains up to the existing 30 currently valid matching candidates in stable ID order, so known stale/excluded entries cannot exhaust a cutoff before later current materials. Source read errors still fail closed; retained results/open actions revalidate, not assume an atomic source snapshot. The isolated retrieval branch requires an empty query and no facets, compares kind by strict string equality, emits a query-only `kind` classification reason, sorts deterministically by ID and applies the existing limit. Score 1 is an equal-type ordering marker, not relevance or confidence. It never invokes the lexical/facet/network branch; ordinary idea and four-facet paths are unchanged.

Result validation and a short-lived WeakMap bind full endpoint evidence plus kind to source-opening actions. Own index/source membership, current kind, identity/hash/privacy/exclusion and full provenance remain mandatory. No clicks/keystrokes are collected. The existing surface shows readable current type, same-type count/reason, honest capped/empty results and unchanged source-origin labels; it reuses selection clearing/breadth retention/cancel-late safeguards. A classification is editorial, not semantic equivalence or causality. This does not make SourcePort reads atomic.

## Natural current admission and quotation proofs

No-selection natural searches request a separate transient continuation of that same score/network pass, including authorised bounded interpretation where already configured. Candidate validation checks all original quotations and the complete current endpoint: source records, memberships, exclusions, revisions, identities and current privacy. Known-invalid candidates may be skipped in stable score/ID order until main seven; unknown reads/exclusion/safety errors propagate as the original failure for the complete query, never a partial commit. No global limit increase, scoring-corpus prefilter, IDF change, extra interpretation, new network walk or result padding.

Every displayed natural, facet or kind quotation is WeakMap-bound to its complete query-time endpoint. Opening one quotation from a merged editorial claim therefore rechecks all donors; a remaining current donor cannot keep an obsolete unioned claim live. After explicitly excluding the changed donor and refreshing, a genuinely rebuilt current card can be opened. Bindings are transient proof metadata, not behavior collection. SourcePort is still non-atomic, and this does not establish native clicks, provider compatibility or new semantic quality. For fully current mixed-privacy duplicates, the endpoint now authenticates each donor then aggregates their canonical privacy with the existing restrictive order, requiring equality with both the query endpoint and stored fragment. An individual ordinary donor need not equal an overall private fragment; unknown privacy and any failed identity/hash/quote/member/exclusion proof still reject the complete card. Cloud eligibility remains the separate unchanged all-normal donor check. No persistence/dedup/scoring/network change or additional read pass.
